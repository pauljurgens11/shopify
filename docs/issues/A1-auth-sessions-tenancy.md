## Context
The skeleton is real but hollow: `apps/api/src/plugins/tenancy.ts` decorates
`request.shopId`/`request.db` and its `onRequest` hook is a deliberate no-op, so
every `request.db` read currently throws. Nothing consumes
`packages/contracts/src/auth.ts` (complete), `@node-rs/argon2`, or `ioredis`
(both already deps). `dbForShop` in `packages/db/src/tenant.ts` is finished and
memoized — you only wire resolution to it. The error shape, `ApiError` helpers,
and rate-limit plugin (registered `global: false` with a SPEC-shaped 429 body)
all exist. Route autoload maps `routes/admin/**` → `/admin/api/**`,
`routes/storefront/**` → `/storefront/api/**`, `routes/api/**` → `/api/**`
(see `app.ts`).

## Build (SPEC §6, §8)
1. **Redis sessions** (`lib/sessions.ts`): create/get/touch/destroy keyed
   `sess:{id}`, value `{ shopId, staffUserId, role, permissions }`, 7-day
   sliding TTL (`SESSION_TTL_DAYS`). Cookie: name from
   `constants.SESSION_COOKIE`, httpOnly, SameSite=Lax, signed, Secure in prod.
2. **Routes** under `routes/auth/`:
   - `POST /auth/signup` — creates Shop + owner StaffUser in one `dbAdmin`
     transaction (one of the sanctioned `dbAdmin` uses), slug from shop name,
     starts a session. Body: `signupInput`.
   - `POST /auth/login` — argon2id verify (`@node-rs/argon2`), per-shop email
     lookup. Rate limit `RATE_LIMITS.login` via the route's `config.rateLimit`.
   - `POST /auth/logout`, `GET /auth/me` (session → staff user + shop).
3. **Tenant resolution** in `plugins/tenancy.ts` `onRequest`:
   - `/admin/api/*` → session cookie → `shopId`; missing/expired → 401.
   - `/storefront/api/*` → Host header slug (reuse the parsing rules from
     `apps/storefront/src/lib/tenant.ts` — port stripped, `{slug}.lvh.me`) →
     shop lookup via `dbAdmin` (platform-level, sanctioned) with a small
     in-process TTL cache → 404 `not_found` if no shop.
   - `/api/*` → `Authorization: Bearer shpat_…` → SHA-256 hash → `App` row →
     `shopId`; wrong/missing → 401.
   - `/auth/*`, `/health`, `/vault/*` resolve nothing (vault resolves its own
     shop — see D1).
4. **requirePermission** (`lib/permissions.ts`): `requirePermission('orders')`
   preHandler factory per SPEC §8 role rules (`owner`/`admin` bypass, `staff`
   checks the boolean map). Export it — every admin route from B/C/D/F/G uses it.
5. **CSRF**: for cookie-authenticated mutations, require header
   `x-requested-with` (see `constants.CSRF_HEADER`); Bearer requests exempt.

## Test plan (write first)
- `apps/api` needs a `vitest.config.ts` (node env) — you create the harness;
  A2 builds the big suite on it. Keep `--passWithNoTests` until A2 removes it.
- `apps/api/test/auth.test.ts` against the compose Postgres + Redis: signup
  creates shop+owner and sets a cookie; login wrong-password → 401 with SPEC
  error shape; `GET /auth/me` round-trips; a request to `/admin/api/*` without
  a session → 401; with a session, `request.db` resolves (probe with a tiny
  temporary route or the shops route).
- Acceptance: `pnpm --filter @merchant/api exec vitest run test/auth.test.ts`
  green with `docker compose up -d` running; `pnpm verify` green.

## Landmines
- `dbAdmin` is legal ONLY in signup, platform auth lookup, migrations/seed
  (SPEC §6). Everything else `request.db`.
- Store the API token **hash**, never the token (SPEC §8); token strings are
  generated by `newApiToken()` in `packages/config/src/ids.ts`.
- Argon2id via `@node-rs/argon2` (prebuilt) — do not add the `argon2` package.
- Session cookie name comes from `constants.SESSION_COOKIE` — there is no env
  var for it (removed deliberately).
- Do not build password reset, email verification, or OAuth — out of scope.
