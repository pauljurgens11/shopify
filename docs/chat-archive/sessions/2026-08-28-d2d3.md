## TDD earned its keep — three real bugs

1. **Stripe fills an absent `decline_code` with `''`**, not `undefined` — the empty string was shadowing `code` and flattening every `expired_card`/`incorrect_cvc` into a generic decline. Caught on the first red run.
2. **Maverick 4xx became a card decline.** `post()` only treated ≥ 500 as transport failure, so a 401 from a revoked API key parsed as an auth response → terminal `declined`. Every customer told their good card failed, no failover — the exact inversion of SPEC §11. Found in my own review pass, now `classifyMaverickStatus`.
3. **Cross-tenant replay leak.** The idempotency cache keyed a process-global map on the caller-supplied key alone. `idempotencyKey` carries no shop, and order numbers are per-shop sequential from #1001 — two shops colliding on one key would hand the second shop the first's approval *and a transaction id it could capture or refund*. Replays now match on a charge fingerprint (never a PAN).

## Testing approach

41 tests, split by what each can actually prove: 12 pure routing (exact weight boundaries plus a seeded 10k-draw distribution), 21 router against real Postgres (idempotency is a unique index and the refund cap is a `SUM` — a fake store proves neither), 9 route-level covering only what's invisible from the package. No per-endpoint CRUD.

## Four bugs the review pass caught

The one that mattered most: **an incomplete routing table could stop a shop taking money.** A single rule of `amex → Stripe` made the chain come back empty for every Visa customer, and the charge died with "No payment processor is connected" while two enabled processors sat right there. Rules are a preference, not a whitelist — no match now falls back to everything enabled.

Also fixed: concurrent same-key charges 500'd on the unique index; `savePaymentMethod` minted `card_tok_` ids for `PaymentMethod` rows; and a failing `onPaid` handler could fail an already-committed charge (G1 will wire that to BullMQ — a Redis blip must not become a checkout error).

## One landmine worth flagging to you directly

`@fastify/autoload` treats a directory's `index.ts` as the **whole directory and silently skips its siblings**. My `routes/admin/payments/index.ts` made `processors.ts` and `routing-rules.ts` vanish with no error — they just 404'd, and only `app.printRoutes()` showed it. Route directories need to stay index-free, like `routes/vault/`. I logged it in `AGENT-LOG.md` since every workstream adding routes will hit it.
