## What's actually built

**Admin: essentially nothing.** 22 files total — [layout.tsx](apps/admin/src/app/layout.tsx), a Polaris + React Query [providers.tsx](apps/admin/src/components/shell/providers.tsx), the complete nav registry (`src/navigation/`), and a placeholder [page.tsx](apps/admin/src/app/page.tsx) that says "Skeleton is up. WS-A: replace with the Frame shell." No Frame, no TopBar, no login, no API client, no store pages.

**Storefront: nothing.** A tenant resolver plus a placeholder home printing the resolved shop slug.

**Theme engine (F1, landed as PR #7): the only real UI so far.** [product-detail.tsx](packages/theme-engine/src/sections/product-detail.tsx), [collection-page.tsx](packages/theme-engine/src/sections/collection-page.tsx), [cart-page.tsx](packages/theme-engine/src/sections/cart-page.tsx), [footer.tsx](packages/theme-engine/src/sections/footer.tsx), announcement bar, the `shared/` primitives (ThemeButton, ProductCard, Price, SectionShell) and three presets are implemented. The 12 marketing sections (hero, slideshow, testimonials, FAQ…) are 21-line `TODO(WS-F)` stubs that render an empty `<section>`.

**In flight:** branches exist for `ws-a/admin-shell` (A3, pushed to origin) and `ws-f/marketing-sections` (F2, local only) — neither is logged as claimed in [AGENT-LOG.md](docs/AGENT-LOG.md), and neither has merged. Everything merged to `main` so far is backend: auth/tenancy (A1), discounts engine (C1), vault + adapters + payment router (D1–D3), theme engine core (F1).

Net: A3 is the gate. All nine admin UI issues depend on it, and it hasn't landed.
